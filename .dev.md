# AzHST development notes

## Debug-only authentication test overrides

Debug builds recognize two presence-based environment variables for testing
the GitHub authentication UI:

| Variable | Debug behavior |
|---|---|
| `TEST_NO_GH_SIGNIN` | Skips the GitHub account check during application startup and starts in the signed-out state. The user can still open the manual sign-in instructions and confirm completion; that confirmation performs the normal account check. |
| `TEST_NO_GH_BIN` | Simulates GitHub CLI being unavailable. Every account check returns the normal missing-`gh` status without starting a `gh` process. |

These overrides are compiled only when the application is built with the
`Debug` configuration. Release builds ignore both variables and do not read
them. Only presence matters; the value is not parsed. `TEST_NO_GH_BIN` takes
precedence when both variables are present.

PowerShell examples:

```powershell
$env:TEST_NO_GH_SIGNIN = "1"
dotnet run --project .\src\AzHST.Desktop\AzHST.Desktop.csproj --configuration Debug
Remove-Item Env:\TEST_NO_GH_SIGNIN
```

```powershell
$env:TEST_NO_GH_BIN = "1"
dotnet run --project .\src\AzHST.Desktop\AzHST.Desktop.csproj --configuration Debug
Remove-Item Env:\TEST_NO_GH_BIN
```

The variables are test controls only. They are not saved to `settings.json`
and must not alter Release authentication behavior.

## Application identity and CI release flow

The Desktop project owns the user-facing application identity:

```xml
<AppName>AzHST</AppName>
<Product>$(AppName)</Product>
<AssemblyTitle>$(AppName)</AssemblyTitle>
<Version>0.0.0</Version>
```

`0.0.0` is the local and non-release fallback. Release CI must override the
standard `Version` property rather than editing the project file. The main
window reads `AssemblyProductAttribute` and
`AssemblyInformationalVersionAttribute` from the built Desktop assembly, so
the application name and displayed version are never duplicated in XAML.
Build metadata after `+`, such as a commit SHA, remains available in the
assembly but is omitted from the normal UI display.

### Release source of truth

Use an annotated or protected Git tag such as `v1.0.0` as the release version
source. A release workflow should:

1. Trigger only for tags matching the repository's release convention.
2. Validate the tag as semantic version text.
3. Remove the leading `v` to obtain the build version.
4. Publish every target with the same `Version`.
5. Let the .NET SDK append the source revision to `InformationalVersion`.
6. Pass the same version to the platform packaging step.
7. Sign the final package where signing is configured.
8. Upload versioned artifacts and checksums to the GitHub release.

Example PowerShell used by a GitHub Actions step:

```powershell
$tag = "${{ github.ref_name }}"
if ($tag -notmatch '^v(?<version>\d+\.\d+\.\d+(?:-[0-9A-Za-z.-]+)?)$') {
    throw "Release tag '$tag' is not a supported semantic version."
}

$version = $Matches.version
"version=$version" >> $env:GITHUB_OUTPUT
```

Publish using the normalized outputs:

```powershell
dotnet publish .\src\AzHST.Desktop\AzHST.Desktop.csproj `
  --configuration Release `
  --runtime win-x64 `
  --self-contained true `
  -p:Version="${{ steps.version.outputs.version }}" `
  -p:ContinuousIntegrationBuild=true
```

The SDK records an informational version such as
`1.0.0+<source-revision>`. AzHST displays `1.0.0` and leaves the complete value
in assembly metadata for diagnostics.

Do not independently assign `AssemblyVersion` or `FileVersion` unless the
project later adopts a specific binary-compatibility policy. The .NET SDK
derives compatible numeric values from `Version`.

### Artifact names

The packaging step must consume the same normalized version output; it must
not parse the version back out of the executable. Use consistent names that
include the product, semantic version, platform, and architecture:

```text
AzHST-1.0.0-win-x64-setup.exe
AzHST-1.0.0-osx-arm64.dmg
AzHST-1.0.0-linux-x64.AppImage
```

Prerelease labels remain in the artifact name:

```text
AzHST-1.1.0-beta.1-win-x64-setup.exe
```

Branch and pull-request builds may retain the `0.0.0` fallback or use a
non-release CI suffix, but they must not publish release installers.

## Application icon assets

AzHST uses an original connected-node letter `A` rather than an official Azure
service mark. The source and generated assets are:

```text
src\AzHST.Desktop\Assets\
  azhst-icon.svg
  azhst-icon.png
  azhst-icon.ico
```

- `azhst-icon.svg` is the editable vector source for future packaging.
- `azhst-icon.png` is the 512-by-512 portable raster asset.
- `azhst-icon.ico` contains Windows sizes from 16 through 256 pixels and is
  configured as the executable icon.

All Avalonia windows use the packaged ICO for their window and taskbar icon.
The main-window sidebar deliberately shows the product name without a separate
logo badge so branding does not consume navigation space.

## Output theme configuration

AzHST keeps output theme requirements in validated JSON files. Settings store
only the selected theme IDs. Theme files contain declarative colors,
typography, appearance, and motion values; they never contain arbitrary CSS,
JavaScript, PresentationML, or prompt text.

Theme definitions intentionally have **no theme `version` property**.
`schemaVersion` identifies the parser contract only. The current supported
schema is `1`, and unknown JSON properties are rejected.

### Files and defaults

```text
resources\
  themes\
    html\
      azure-night.json
    presentation\
      professional-light.json
```

The Desktop project copies this directory to
`resources\themes` beside the application executable. The composition root
loads it through `FileOutputThemeCatalog.CreateDefault()`.

Default selections:

| Output | Theme ID |
|---|---|
| HTML visualization | `azure-night` |
| PowerPoint presentation | `professional-light` |

The user can change both selections in **Settings**. The selected IDs are
persisted in `settings.json`:

```json
{
  "themes": {
    "htmlThemeId": "azure-night",
    "presentationThemeId": "professional-light"
  }
}
```

Missing or blank IDs from older settings files are normalized to the defaults.
An ID that is present but not available in the catalog produces an explicit
configuration error when that output is generated.

### Shared validation

Every theme must provide:

- `schemaVersion`: integer `1`
- `id`: lowercase letters, digits, and hyphens; must match
  `[a-z0-9][a-z0-9-]{0,63}`
- `displayName`: non-empty, at most 80 characters, with no control characters

Additional rules:

- JSON must deserialize strictly; unknown properties are errors.
- Each output-kind directory must exist and contain at least one `.json` file.
- IDs must be unique within the HTML or presentation catalog.
- Colors must use `#RRGGBB`.
- Font-family values permit only letters, digits, spaces, commas, periods,
  apostrophes, quotation marks, underscores, and hyphens.
- Required text/background combinations must meet a WCAG contrast ratio of
  at least `4.5:1`.

## HTML theme schema

`resources\themes\html\<id>.json` has this shape:

```json
{
  "schemaVersion": 1,
  "id": "azure-night",
  "displayName": "Azure Night",
  "palette": {},
  "typography": {},
  "appearance": {},
  "motion": {}
}
```

### `palette`

All values are required `#RRGGBB` colors:

| Property | Use |
|---|---|
| `page` | Page background |
| `surface` | Primary cards and panels |
| `surfaceRaised` | Elevated or emphasized panels |
| `surfaceSelected` | Selected and active surfaces |
| `border` | Borders and dividers |
| `text` | Primary text |
| `textMuted` | Secondary text |
| `primary` | Primary controls and structure |
| `activeFlow` | Active connectors and animated flow |
| `accent` | Secondary emphasis |
| `success` | Positive state |
| `warning` | Warning state |
| `danger` | Error or destructive state |
| `focus` | Keyboard focus indicator |
| `iconTile` | Background behind official Azure icons |

Contrast checks cover `text` on `page`, `text` on `surface`, and `textMuted`
on `surface`. When `appearance.allowPureBlack` is `false`, no palette value
may be `#000000`.

### `typography`

| Property | Validation |
|---|---|
| `fontFamily` | Validated font-family string, maximum 200 characters |
| `baseSizePixels` | `12` through `24` |
| `lineHeight` | `1.2` through `2.0` |

### `appearance`

| Property | Values or validation |
|---|---|
| `colorScheme` | `dark` or `light` |
| `surfaceStyle` | `layered` or `flat` |
| `iconTreatment` | `lightTile` or `surfaceTile` |
| `allowPureBlack` | Boolean |
| `allowGlassmorphism` | Boolean |
| `maximumGradients` | `0` through `3` |
| `cornerRadiusPixels` | `0` through `24` |
| `iconTileSizePixels` | `24` through `80` |

### `motion`

| Property | Validation |
|---|---|
| `transitionDurationMilliseconds` | `0` through `1000` |
| `sequenceStepDurationMilliseconds` | `100` through `5000` |
| `allowContinuousDecorativeMotion` | Boolean |

The generated page must still implement `prefers-reduced-motion` behavior.
Theme motion values control timing and whether the Copilot prompt may permit
continuous decorative motion; they do not weaken the accessibility baseline.

### HTML application

`GenerateVisualizationUseCase` resolves the selected theme before generation.
The typed values are converted into trusted Copilot requirements; no free-form
theme prompt is loaded from JSON.

After Copilot returns HTML, `GeneratedHtmlDocumentProcessor`:

1. Removes any model-provided `style#azh-output-theme`.
2. Replaces any existing `data-azh-theme` attribute.
3. Adds `data-azh-theme="<selected-id>"` to the root `<html>` element.
4. Injects an authoritative `style#azh-output-theme` after model styles.
5. Applies the selected page background, text, typography, color scheme, and
   focus baseline.

The injected CSS variables are:

```text
--azh-page
--azh-surface
--azh-surface-raised
--azh-surface-selected
--azh-border
--azh-text
--azh-text-muted
--azh-primary
--azh-flow-active
--azh-accent
--azh-success
--azh-warning
--azh-danger
--azh-focus
--azh-icon-tile
--azh-font-family
--azh-base-size
--azh-line-height
--azh-corner-radius
--azh-icon-tile-size
--azh-transition-duration
--azh-sequence-step-duration
```

Copilot is instructed to consume these variables rather than redefine them.

## PowerPoint theme schema

`resources\themes\presentation\<id>.json` has this shape:

```json
{
  "schemaVersion": 1,
  "id": "professional-light",
  "displayName": "Professional Light",
  "palette": {},
  "typography": {},
  "appearance": {}
}
```

### `palette`

All values are required `#RRGGBB` colors:

| Property | Use |
|---|---|
| `canvas` | Slide background |
| `surface` | Header, cards, labels, and light theme slot |
| `summarySurface` | Summary callout fill |
| `title` | Deck and slide titles |
| `text` | Body and node text |
| `textMuted` | Details, sources, connector labels, and footer |
| `border` | Card and label borders |
| `primary` | Header rule, normal node outline, and connectors |
| `accent` | Secondary Office theme accent |
| `iconTile` | Azure icon tile fill |
| `success` | Office theme success accent |
| `warning` | Office theme warning accent |
| `comparison` | Comparison-card outline and Office theme accent |
| `danger` | Office theme danger accent |
| `hyperlink` | Office hyperlink color |
| `followedHyperlink` | Office followed-hyperlink color |

Contrast checks cover `title`, `text`, and `textMuted` on `canvas`, plus
`text` on `surface`.

### `typography`

PowerPoint sizes are integer points:

| Property | Range |
|---|---|
| `fontFamily` | Validated font name, maximum 80 characters |
| `displayFontFamily` | Validated font name, maximum 80 characters |
| `titleSizePoints` | `24` through `44` |
| `subtitleSizePoints` | `12` through `24` |
| `slideTitleSizePoints` | `16` through `28` |
| `summarySizePoints` | `10` through `20` |
| `bodySizePoints` | `12` through `24` |
| `nodeLabelSizePoints` | `8` through `18` |
| `nodeDetailSizePoints` | `7` through `14` |
| `connectionLabelSizePoints` | `6` through `12` |
| `footerSizePoints` | `6` through `12` |

Title and slide-title runs use `displayFontFamily`; other runs use
`fontFamily`. Both are also written into the package's Office theme.

### `appearance`

| Property | Values |
|---|---|
| `roundedCards` | Boolean |
| `showHeaderRule` | Boolean |
| `iconTreatment` | `lightTile` or `none` |

### PowerPoint application

`GeneratePresentationUseCase` resolves the selected presentation theme after
the Copilot slide plan has passed validation. `OpenXmlPresentationBuilder`
maps the typed theme to native DrawingML colors, fonts, sizes, card geometry,
header treatment, icon tiles, connectors, and the package theme.

Geometry, slide bounds, connector routing, arrow direction, and Office package
structure remain deterministic code. JSON cannot inject Open XML.

## Adding a theme

1. Copy an existing definition in the matching directory.
2. Give it a unique stable `id` and user-facing `displayName`.
3. Change only typed schema values; do not add a theme `version` property.
4. Keep every color in `#RRGGBB` form and satisfy contrast requirements.
5. Run:

   ```powershell
   dotnet test .\tests\AzHST.Infrastructure.Tests\AzHST.Infrastructure.Tests.csproj
   dotnet test .\tests\AzHST.Application.Tests\AzHST.Application.Tests.csproj
   ```

6. Start AzHST, open **Settings**, select the new theme, and generate the
   corresponding output type.

No code change is needed when the new file uses the existing schema. A schema
change requires updates to the typed Application model, catalog validation,
deterministic renderer, tests, and `schemaVersion`.
